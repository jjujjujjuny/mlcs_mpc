# 캘리브레이션 — mocap 을 자로 쓴다

MPC 는 "명령한 대로 차가 움직인다" 를 전제로 1초 앞을 예측한다.
그 전제가 틀리면 예측이 통째로 틀리고, 게인을 아무리 튜닝해도 낫지 않는다.

**이 문서의 절차를 끝내기 전에는 저속(1~1.5 m/s)으로만 주행하세요.**

---

## 왜 이게 먼저인가 — 실제 사례

26-jetson 저장소 2호차는 `speed_to_erpm_gain` 이 1호차 값(4203)을 그대로
빌려 쓴 상태로 달렸다. 나중에 재보니 정답은 4403 이었다:

```
지령 3.0 m/s → erpm 4203×3.0 = 12609 → 실제 12609/4403 = 2.864 m/s
                                      → odom 은 12609/4203 = 3.000 이라 보고
```

**차는 4.5% 느리게 달리고, odom 은 거리를 4.8% 과대보고** 하고 있었다.
그 상태에서 잰 다른 값들(`speed_lag`, `slip_gain`)도 전부 다시 재야 했다.

우리는 mocap 이 있다. 줄자보다 정확하고 빠르다 — 처음부터 제대로 재자.

## 준비

```bash
# 터미널 1 — mocap
ros2 launch natnet_ros2 natnet_ros2.launch.py ...

# 터미널 2 — mocap 브릿지
ros2 run mlcs_mpc mocap_bridge --ros-args \
    --params-file ~/mlcs_mpc/src/mlcs_mpc/config/mocap.yaml

# 터미널 3 — VESC 드라이버
ros2 launch f1tenth_stack bringup_launch.py
```

확인:
```bash
ros2 topic hz /mpc/state      # 100Hz 근처
```

> 조이스틱으로 차를 옮겨야 하면 터미널을 하나 더 띄우세요.
> **`joy:=false` 를 꼭 붙이세요** — bringup 이 joy_node 를 이미 띄웁니다.
>
> ```bash
> ros2 launch mlcs_mpc joystick.launch.py joy:=false
> ```
>
> 캘리브레이션 중에는 `calibrate` 노드가 `/drive` 로 명령을 내고, 조이스틱은
> `/teleop` 으로 냅니다. mux 우선순위상 **조이스틱이 이기므로**, RT 를 건드리면
> 측정이 오염됩니다. 측정 중에는 조이스틱에서 손을 떼세요.

> ⚠ **넓은 공간에서, 킬스위치를 손에 들고** 하세요.
> `steer` 모드는 차가 원을 그리며 돕니다.

## 순서 — 이 순서를 지킬 것

뒤 단계가 앞 단계에 의존한다. `speed` 가 틀리면 그 위 전부가 틀린다.

### ① 조향 중립 (offset)

직진 명령을 줬을 때 실제로 직진하는가?

```bash
ros2 run mlcs_mpc calibrate --ros-args -p mode:=neutral -p speed_for_steer:=1.0
```

출력의 "등가 조향각" 이 0 에 가까워야 한다. 아니면 안내대로
`f1tenth_stack/config/vesc.yaml` 의 `steering_angle_to_servo_offset` 을 고친다.

```yaml
steering_angle_to_servo_offset: 0.5304   # ← 이 값을 고친다
```

**고친 뒤 다시 재서 요레이트가 0 에 가까워졌는지 확인한다.** 한 번에 안 맞으면
반복한다.

### ② 속도 게인

```bash
ros2 run mlcs_mpc calibrate --ros-args -p mode:=speed -p value:=1.5
ros2 run mlcs_mpc calibrate --ros-args -p mode:=speed -p value:=2.5   # 다른 속도로도
```

두 속도에서 나온 보정계수가 비슷해야 한다. 많이 다르면 선형 가정이
안 맞는 것이니 (배터리 전압 강하, 마찰) 실제 주행 속도 범위에서 재라.

```yaml
speed_to_erpm_gain: 4614.0    # ← 출력이 알려주는 값으로 고친다
```

> **부호 주의:** 양수 speed 명령에 차가 **후진** 하면 gain 부호가 반대다.
> 26-jetson 2호차가 실제로 그랬고, 그 탓에 SLAM 맵이 방사형으로 깨졌다.
> 조이스틱만 invert 로 덮여 있어서 수동 주행은 정상처럼 보였다 —
> **증상을 덮으면 원인이 숨는다.**

### ③ 조향 게인

좌우 **양쪽** 을 잰다.

```bash
ros2 run mlcs_mpc calibrate --ros-args -p mode:=steer -p value:=0.2
ros2 run mlcs_mpc calibrate --ros-args -p mode:=steer -p value:=-0.2
```

좌우 비율이 다르면 ①의 중립이 아직 안 맞은 것이다 — ①로 돌아간다.

```yaml
steering_angle_to_servo_gain: -1.2135   # ← 출력이 알려주는 값
```

> 26-jetson 은 손으로 밀어 그린 원에서 얻은 값이 22% 틀렸고, 주행 로그로
> 다시 잡았다. **차가 실제로 달리는 상태에서** 재는 것이 중요하다 —
> 정지 마찰과 주행 중 타이어 거동이 다르기 때문이다.

### 수동 원선회 — 랠리 모드

`calibrate` 는 한 번에 한 조건만 잰다. 여러 조건을 손으로 빠르게 훑을 때는 랠리
모드를 쓴다. **RT 끝까지 = 최대 속도, 스틱 끝까지 = 최대 조향** 이므로, 끝까지
당기고 밀기만 하면 입력이 일정하다. `/mpc/state` 와 명령이 함께 기록된다.

```bash
./drive.sh rally            # ~/mlcs_data/drive_<시각>_rally.csv
./drive.sh rally steer30    # 태그를 붙이고 싶을 때
```

| 십자키 | 동작 | 한 칸 | 시작값 | 한도 |
|---|---|---|---|---|
| 위 / 아래 | 최대 속도 ± | 0.05 m/s | 1.00 m/s | 3.0 m/s |
| 오른 / 왼 | 최대 조향 ± | 0.01 rad | 0.20 rad | 0.40 rad |

한 번 누르면 한 칸 움직이고, 터미널에 예상 반경과 횡가속도가 찍힌다. 값은
`config/joystick.yaml` 의 `rally_*` 로 바꾼다. 다시 켜면 시작값으로 돌아간다.

순서: 1 m/s 에서 좌우 각각 정상 선회를 몇 바퀴씩 돈다.

| 최대 조향 | 예상 반경 | 1 m/s 횡가속도 |
|---|---|---|
| 0.20 rad | 1.63 m | 0.61 m/s² |
| 0.30 rad | 1.07 m | 0.94 m/s² |
| 0.40 rad | 0.78 m | 1.28 m/s² |

±0.10 rad 는 반경 3.3 m 라 실험실(최대 내접원 2.08 m)에서 원을 못 그린다.

> 원을 그린 데이터는 `./drive.sh cleanlog` 의 대상(`drive_*.csv`)에 들어간다.
> HyperPM 데이터를 다시 만들 때 원선회 구간이 섞이는 것을 감안한다.

### ④ 휠베이스

줄자로 앞바퀴축 중심 ~ 뒷바퀴축 중심.

```yaml
# config/vehicle.yaml
wheelbase: 0.33
```

교차 검증: ③에서 나온 선회반경 R 과 조향각 δ 가
`tan(δ) = L/R` 을 만족해야 한다.

### ⑤ 최대 조향각

서보를 기구 스토퍼까지 돌려서 확인한다. 스토퍼를 넘게 명령하면 서보가
계속 힘을 쓰다 탄다.

```yaml
max_steer: 0.36    # rad
```

|---|---|---|

## 검증 — 잘 됐는지 어떻게 아는가

캘리브레이션 후 원을 한 바퀴 돌려보고:

```bash
ros2 topic echo /mpc/state --field twist.twist.linear.x
```

- 명령 속도와 실제 속도가 **5% 이내**
- 좌/우 선회반경이 **비슷**
- 직진 명령에서 요레이트가 **0 근처**

세 가지가 다 맞으면 속도를 올려도 된다. `config/vehicle.yaml` 의
`max_speed` 를 0.5 m/s 씩 올리면서, 매번 경로 추종 오차를 확인한다.

## 다음에 재야 할 것 (동역학 모델로 갈 때)

| 값 | 방법 | 상태 |
|---|---|---|
| `mass` | 저울 | ✅ **3.284 kg** (2026-11-05, 라이다 포함) |
| `lf`, `lr` | 앞/뒤 축을 각각 저울에 올려 하중 분포로 계산 | ✅ **0.1763 / 0.1537** |
| `mu` | 차를 옆으로 저울로 밀어 운동 마찰력 측정 (3284 g 대비) | ✅ **0.41** (2026-11-04) — 옆 최대정지 0.45. 뒤→앞 0.48/0.45 (네 바퀴 잠금) |
| `I_z` | 이선 진자 (아래) — 안 재고 계산해도 자릿수는 맞다 | ⚠ **0.089** 추정 (2026-11-05) |

### I_z (요 관성모멘트) — 추정으로 넣어둠

재지 않고 계산했다. **독립적인 두 방법이 1% 안에서 일치**해서 자릿수를
틀릴 일은 없다:

```
균일 평판   m(a²+b²)/12 = 3.284·(0.505² + 0.27²)/12 = 0.0897
동적지수 1   m·lf·lr     = 3.284·0.1763·0.1537       = 0.0890
회전반경    k = sqrt(I/m) = 0.165 m  — 전장의 33%. 타당하다.
```

> ⚠ **논문 기본값 0.46 을 베껴 쓰지 말 것.** 5.1 kg 에서 0.46 이면
> k = 0.300 m 인데, 길이 0.505 m 물체의 *이론 최대* k 는 a/2 = 0.253 m 다
> (질량이 양 끝에 몰린 막대). 물리적으로 불가능하므로 측정치가 아니라
> `single_track_params.py` 의 학습 파라미터 초기값이다 — HyperPM 이
> 예측하는 10개 중 하나다. 같은 식으로 논문 차를 추정하면 0.126 이다.

#### 제대로 재려면 — 이선(bifilar) 진자

차를 **두 줄에 수평으로** 매달고, 수직축 둘레로 살짝 비튼 뒤 주기를 잰다.

```
I_z = m·g·(d/2)²·T² / (4π²·Ls)

  d  = 두 줄 사이 간격 [m]
  Ls = 줄 길이 [m]
  T  = 비틀림 진동 주기 [s]
```

| d | Ls | 예상 주기 T | 10회 |
|---|---|---|---|
| 0.10 m | 0.8 m | **5.9 s** | 59 s |
| 0.10 m | 1.5 m | 8.1 s | 81 s |
| 0.20 m | 0.8 m | 3.0 s | 30 s |

**줄을 좁게(10 cm) 매다는 쪽이 낫다** — 주기가 길어져 스톱워치 오차가
묻힌다. 10회를 재서 나누면 1% 아래로 떨어진다.

주의할 것:
- 두 줄이 **무게중심을 가운데 두고** 좌우 대칭이어야 한다 (앞축에서
  0.1802 m 지점). 안 맞으면 비틀림에 흔들림이 섞인다.
- 비트는 각도는 작게 (±10° 이내). 크면 선형 근사가 깨진다.
- 차가 수평이어야 한다. 기울면 다른 축 관성이 섞인다.

#### 지금 당장 급하지 않은 이유

저속(0.7~1.5 m/s)에서는 요 동역학이 MPC 지평보다 훨씬 빨라 운동학 모델과
차이가 거의 없다. 그리고 HyperPM 이 `I_z` 를 데이터에서 다시 잡는다 —
물리 추정은 그 **사전값**으로 쓰면 충분하다.

### 질량·무게중심 측정법 (2026-10-02, 2026-11-05 실시)

세 번 잰다 — **전체 / 앞축만 / 뒤축만**.

```
앞축 1529 g   뒤축 1753 g   전체 3284 g     (2026-11-05, 라이다 포함)
검산: 1529 + 1753 = 3282  vs  3284  →  −2 g (−0.06%)  ✓

앞축 1400 g   뒤축 1685 g   전체 3097 g     (2026-10-02, 라이다 전)
```

> ★ **반대쪽 바퀴를 같은 높이에 받쳐야 한다.** 한쪽만 저울에 올리면 차가
> 기울어져 하중이 옮겨간다. 저울 두께만큼 받침을 괸다.
>
> 검산이 1% 이내면 정상. 넘으면 기울었거나 저울 영점이 틀어진 것이다.
>
> 받침을 못 괴어도 앞뒤를 **같은 각도**로 재면 `l_f`, `l_r` 은 맞다. 기울기 항이
> `l_r = L/2 + L(F_f−F_r)/(2m)` 에서 빠지기 때문이다. 2026-11-05 측정은 약 5 cm
> 들어 약 8.9° 기울어졌다. 각도가 앞뒤로 다르면 이 식도 틀린다.

무게중심 위치는 지렛대 원리로 나온다:

```
l_f = L × F_r/(F_f+F_r)      앞축 ~ 무게중심
l_r = L × F_f/(F_f+F_r)      뒤축 ~ 무게중심
```

**★ 분자가 교차한다.** 앞축에서 무게중심까지의 거리(`l_f`)는 **뒤축 하중**에
비례한다 — 뒤가 무거우면 무게중심이 뒤로 가므로 `l_f` 가 커진다. 헷갈리기
쉬운 지점이다.

검산: `l_f + l_r = L` 이 정확히 맞아야 한다 (0.1763 + 0.1537 = 0.3300 ✓).
