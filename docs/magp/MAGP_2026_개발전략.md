## 0. 한 줄 요약

**대회장엔 Motive가 없다.** 지금 차는 mocap이 `/mpc/state`를 채워 줘야 움직이므로, 최우선 과제는 MPC가 아니라
**LiDAR 기반 localization으로 `/mpc/state`를 채우는 것**이다. MPC는 그와 병렬로 Motive 환경에서 개발하고,
마지막에 입력만 갈아 끼운다.

예선 순위는 "베스트 랩"보다 **무충돌 연속 랩 수**가 사실상 결정한다(3회 결과). → 빠른 차보다 **5분 동안 안 부딪히는 차**가 먼저.

## 1. 아키텍처 — 교체점은 `/mpc/state` 하나

```
[연구실]  /natnet_ros/car/pose ─ mocap_bridge ─┐
                                               ├─→ /mpc/state (Odometry) ─→ mpc_node / stanley_node / pp
[대회장]  /scan ─┐                              │        ↑ /mocap/valid (→ /loc/valid 로 일반화)
          /imu ─┼─ Cartographer(pure loc) ─ /tracked_pose ─┐
          /vesc/odom(adaptive gain) ─ velocity ref ────────┼─ EKF ─ lidar_bridge ─┘
                                                           │
          [백업] particle_filter(range_libc GPU) ──────────┘
```

- 컨트롤러는 손대지 않는다. `mocap_bridge`와 같은 인터페이스(`/mpc/state`, `/loc/valid`)를 내는 **`lidar_bridge`** 를 만든다.
- 위치 소스가 끊기면 `/loc/valid=false` → 기존 safety 로직 그대로 정지.
- 연구실에서는 **Motive와 LiDAR 체인을 동시에** 돌려 bag으로 비교할 수 있다. 이게 UNICORN에도 없는 우리 이점이다 — 정답(GT)으로 odom gain·localization 오차·지연을 숫자로 맞춘다.

## 2. Localization 계획

### 2-1. 메인: Cartographer pure localization (ROS 2 Humble `cartographer_ros`)
UNICORN 공개값을 시작점으로.

```lua
-- localization.lua (mapping.lua와 분리)
TRAJECTORY_BUILDER.pure_localization_trimmer = { max_submaps_to_keep = 3 }
POSE_GRAPH.optimize_every_n_nodes = 2            -- 자주·작게 보정 → 위치 점프 작아짐 (매핑은 20)
TRAJECTORY_BUILDER_2D.ceres_scan_matcher.rotation_weight = 0.1
TRAJECTORY_BUILDER_2D.num_accumulated_range_data = 10
TRAJECTORY_BUILDER_2D.max_range = 10.            -- 코스 밖 체육관 벽 제외 (LiDAR 사양에 맞춤)
POSE_GRAPH.constraint_builder.fast_correlative_scan_matcher.linear_search_window = 1.0
POSE_GRAPH.constraint_builder.fast_correlative_scan_matcher.angular_search_window = math.rad(20.)
POSE_GRAPH.global_sampling_ratio = 0.0           -- 전역 탐색은 별도 LUT 노드가 담당 (3절)
options.use_odometry = false                     -- odom을 PGO에서 제외, launch remap으로 extrapolation에만
options.use_imu_data = true
options.tracking_frame = "vesc_imu_rot"          -- 2-3 TF 참고
```

- **휠 odom을 그래프 최적화에서 빼는 이유**: 슬립 구간에서 odom 제약이 최적화를 망쳐 drift↑. 속도 예측(extrapolation)에는 계속 쓴다.
- **긴 직선 주의**: 10m급 LiDAR로 20m 직선을 달리면 LiDAR+IMU만으로는 "정지"로 오판한다. odom 선속도가 반드시 들어가야 한다 (MAGP 코스 20–30m).
- 출력 `/tracked_pose` → `robot_localization` EKF(`/vesc/odom` + IMU 고주파, `/tracked_pose` 저주파·cov 0.001) → `lidar_bridge` → `/mpc/state`.
- 초기 위치: RViz `2D Pose Estimate` → `/finish_trajectory` + `/start_trajectory(use_initial_pose, relative_to_trajectory_id=0)` 재시작 노드(UNICORN set_pose_v2_node 이식). 3절 LUT가 자동으로 `/initialpose`를 쏜다.

### 2-2. 백업: Particle Filter (mit-racecar `particle_filter` + `range_libc` CUDA)
- 같은 맵(png/yaml)으로 launch 인자 `localization:=pf` 전환.
- Orin Nano GPU로 `RMGPU` 백엔드 → 파티클 1만~2만 개를 40Hz. UNICORN의 "PF는 고속에서 불안정"은 파티클 수 제약도 한몫.
- 모션 노이즈(`MOTION_DISPERSION_*`)는 Motive 대비 bag으로 "정답을 간신히 감쌀 만큼" 튜닝.
- 선택 기준(11/5): 같은 bag에서 Motive 대비 **RMSE, 헤딩 오차, 점프 횟수(>10cm/프레임), 지연**을 Carto vs PF로 비교 → 고속에서 덜 벌어지는 쪽이 메인.

### 2-3. TF (Cartographer 함정)
- `base_link` = 뒷축 중심, 지면(z=0). `base_link → laser`는 translation만, rotation 0. LiDAR 수평은 **하드웨어로**(RViz Intensity, Autocompute OFF로 확인, 쇼크 나사로 조정).
- `tracking_frame`은 IMU와 **회전만** 달라야 한다. IMU가 틀어져 있으면 중력 초기화에서 맵이 뒤집힌다.
  `base_link → vesc_imu_rot`(translation만) → `vesc_imu`(rotation만), `tracking_frame = "vesc_imu_rot"`.
- VESC IMU: 펌웨어 6.05, App Settings→IMU 활성화, `vesc/sensors/imu/raw` 축 확인 후 rpy(0/±90/180°) 결정.

### 2-4. 휠 odom 품질 (localization의 밑바닥)
- ERPM gain 이론값 `60·pole_pairs·gear_ratio/(2π·r)` → **Motive 속도 vs /vesc/odom 속도** bag 비교로 보정. (docs/CALIBRATION.md의 speed 캘리브레이션과 통합)
- **Adaptive gain** `gain = gain0 + σ·a_x(LPF) + δ`: 가속 시 과대·제동 시 과소 추정 보정. σ, δ는 rqt 파라미터로 노출 → 미끄러운 판 구간 현장 대응.
- Servo gain/offset: ±0.25rad 범위에서 원주행 `R = L/tan(δ)` 실측. offset≈0.5(혼 중앙).

### 2-5. 매핑 절차 (현장 연습 세션)
1. `low_level` 띄우고 bag 녹화(`/scan /imu /vesc/odom /tf`) 하면서 조이스틱으로 **센터라인 따라 2바퀴**, 급조향 금지.
2. bag으로 **오프라인** Cartographer 매핑(현장 PC) → pbstream/png/yaml.
3. 맵 → centerline → raceline → 속도 → LUT 생성을 **스크립트 하나**로. 목표 15분.
4. 덕트 이음새로 새는 빔: `max_range` 제한 + 맵 erosion(Grid Filter식) 으로 트랙 밖 점 제거.

## 3. 전역 초기화 — 사전 계산 스캔 LUT (브루트포스)

**목적:** 차를 트랙 어디에 두어도 버튼 한 번에 위치를 잡고, 주행 중 위치를 잃어도 자동 복구.

**원리:** 연습 세션에서 맵이 나오면 트랙 위 **모든 (x, y, θ) 후보의 예상 스캔을 미리 레이캐스팅해 표로 저장**. 실전에서는 실제 스캔을 표와 대조만 한다. (UNICORN PF 글의 "Giant LUT" — 트랙 하나는 작아서 RAM 문제 없음.)

| 항목 | 값 |
|---|---|
| 후보 격자 | 주행 가능 셀 5cm (~3.5만) × 헤딩 10° (36) ≈ **130만 pose** |
| 빔 | 1081 → 108 다운샘플, uint16(cm) |
| 표 크기 | 130만 × 108 × 2B ≈ **280MB** (헤딩 5°면 560MB) |
| 생성 | range_libc CUDA 레이캐스팅 1.4억 회 → **수 초** (연습 세션 중 1회, 맵 바뀌면 재생성) |
| 질의 | 실스캔 vs 130만 행 L1/가우시안 점수 → GPU 수십 ms, CPU numpy ~1s |
| 정밀화 | 1위 근처 ±10cm, ±10°만 즉석 레이캐스팅으로 1cm·1° |
| 출력 | `/initialpose` → Cartographer trajectory 재시작 |

**애매함 처리(덕트 직선 대칭):** 1위·2위 점수 차가 임계 이하면 "애매" 표시 → 1~2m 굴린 뒤 두 스캔 점수 합산. 후보별 점수를 전부 갖고 있어 자연스럽다.

**점수 함수:** PF 측정모델과 동일(가우시안). 덕트 이음새로 샌 빔은 "실제 > 예상"이므로 그 방향 패널티를 약하게.

**부수 효과:**
- 주행 중 매 스캔 표 대조(수십 ms) → Cartographer 결과와 크게 어긋나면 자동 재초기화(위치 잃은 채 벽으로 가는 사고 방지).
- 같은 표가 PF 측정모델이라 백업 PF도 레이캐스팅 없이 표 조회로 가능.

**구현물:** `tools/build_scan_lut.py`(맵 → .npy), `lidar_global_init` 노드(스캔 → initialpose, 조이스틱 버튼 바인딩). 예상 1.5일.

## 4. 제어 계획

### 4-1. 안전 기본 차량 (예선 1회차·결승 기본)
- 현재 Pure Pursuit/Stanley + LiDAR localization으로 **5분 무충돌 연속 주행**이 1차 목표.
- PP 보강(UNICORN): 속도·곡률 적응 lookahead `L1 = m_l1·v − c_κ·κ̄·v² + q`, clip[max(0.7, √2·e_lat), 8]; 잔차 헤딩 PD(0.4~0.8 / 5~10%); **마찰원 속도 클램프** `a_long = min(a_max, √(a_tot² − a_lat²))`; **AEB**(local waypoint 비정상 시 정지 — 결승 전 기능점검 "장애물 앞 정지"에 사용).
- 증상표: 직선 진동→m_l1↑ / 코너 커팅→m_l1↓ / 진입 언더스티어→c_κ↑ / 저속 진동→t_clip_min↑.

### 4-2. MPC (예선 2회차·결승 공격 세팅)
- 기존 iLQR 운동학 MPC(시뮬 검증 완료)를 Motive에서 실차 검증 → 11/10까지 PP보다 **표준편차**가 작지 않으면 대회는 PP로 간다.
- 레퍼런스: raceline json `[s, d, x, y, d_r, d_l, psi, kappa, vx, ax]`. 속도는 곡률 기반 velocity planner(`v = √(a_y,max/|κ|)` → fwd/bwd pass → MA 51)로 생성, a_y,max는 보수적(3.0 m/s²)부터.
- Frenet 변환(`/odom_frenet`: s, d, e_ψ)은 직전 s 근방만 탐색(얇은 덕트 벽 반대편 점프 방지). 솔버 실패 시 PP로 fallback, **빈 경로는 절대 컨트롤러에 넘기지 않는다.**
- 결승 추월: 시간 남으면 Grid Filter(erosion 0.25m) → ABD 클러스터링(10점, 0.2~0.5m) → Frenet 등속 EKF 추적 → TRAILING/OVERTAKE 상태기계. 아니면 TRAILING(앞차 따라가기 + 거리 유지)만.

### 4-3. 세팅 2벌
- `safe.yaml`: 섹터 속도 스케일 낮게, a_y,max 보수, lookahead 길게. 예선 1회차·결승 기본.
- `attack.yaml`: 예선 2회차에서만. **주행 중 원격 파라미터 변경 금지** → 정지 후 프리셋 전환.

## 6. 역할

- **설승곤**: Cartographer/PF/EKF 체인, `lidar_bridge`, 스캔 LUT 전역 초기화, Motive 대비 평가 스크립트.
