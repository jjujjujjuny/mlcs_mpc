# 로드맵 — 여기서 HyperMPC 까지

## 지금 어디까지 와 있나

```
[1단계] 운동학 MPC + mocap 위치추정          ← ★ 지금 여기 (시뮬 검증 완료)
[2단계] 실차 검증 + 파라미터 동정
[3단계] 동역학 모델 (Pacejka 타이어)
[4단계] HyperPM — 시변 파라미터 신경망
[5단계] HyperMPC
```

## HyperMPC 가 실제로 무엇인가

논문: [Beyond Constant Parameters: Hyper Prediction Models and HyperMPC](https://arxiv.org/abs/2508.06181)
(Węgrzynowski et al., Poznan University of Technology / IDEAS, 2025)
코드: <https://github.com/hyper-mpc/hypermpc_code>

핵심 아이디어는 **모델 파라미터를 상수가 아니라 시간의 함수로 두는 것**이다.

보통의 MPC 는 예측 구간 전체에서 타이어 마찰 μ, 코너링 강성 같은 값을
하나로 고정한다. 그런데 실제로는 이 값들이 계속 변한다 — 타이어가 데워지고,
하중이 옮겨가고, 노면이 달라진다.

```
θ[t, t+tp] = HyperPM( x[t-th, t], u[t-th, t], û[t, t+tp] )
                       상태 이력    제어 이력   ★ 계획된 미래 제어
```

신경망이 "앞으로 파라미터가 이렇게 변할 것" 이라는 **궤적**을 내놓고,
그것을 공칭 모델에 주입한 뒤 MPC 를 푼다.

### ★ 계획된 미래 제어를 입력으로 받는 것이 결정적이다

논문의 ablation (Table 6): 이 입력을 빼면(HyperPM-EAC) F1TENTH 예측 정확도가
**16.32% 나빠져서**, 기존 HyperDynamics(10.22%)보다 **더 나쁘다.**

> "시변 파라미터를 예측하는 능력은, 시스템의 예상 변화에 대한 정보가
>  충분하지 않으면 **오히려 해가 될 수 있다**"

즉 "앞으로 이렇게 조종할 것이다" 를 알아야 "그러면 파라미터가 이렇게
변하겠다" 를 예측할 수 있다. 이게 기존 방법과의 본질적 차이다.

### 논문 결과 (F1TENTH)

| 항목 | 수치 |
|---|---|
| 장기 예측 오차 | 상수 파라미터 대비 **48.75% 개선** |
| 주행 성능 | residual 모델 대비 **약 19% 개선** |
| **MPC 솔버 시간** | **10.61ms** (상수 모델 10.53ms — 거의 동일) |
| 신경망 추론 | **1.85ms** |

**계산 비용이 거의 안 늘어난 것이 이 방법의 진짜 강점이다.** 파라미터
궤적을 넣어줄 뿐, 솔버 안의 모델 복잡도는 그대로다.

> ⚠ **예측 정확도 1등이 주행 1등이 아니다.** residual 모델은 예측 오차가
> 가장 낮았는데(62.08% 개선) 주행 성능은 HyperPM 보다 나빴다. 논문은 이를
> 일반화 실패로 설명한다 — 수동 주행 데이터 분포와 MPC 주행 분포가 다르기
> 때문이다. **우리도 예측 오차만 보고 판단하면 안 된다.**

### 논문의 실험 구성 — 우리와 거의 같다

| | 논문 | 우리 |
|---|---|---|
| 위치추정 | **OptiTrack** | OptiTrack ✅ **동일** |
| 트랙 | 빈 공간에 **가상 트랙** | 같은 방식 가능 ✅ |
| 속도 | pose 를 **Savitzky-Golay 미분** | 칼만 필터 (같은 문제, 다른 해법) |
| 데이터 | **100Hz 동기, 36분** | `data_logger` 로 수집 중 |
| 차량 | Xray GTXE'22 **1/8, 4WD** | f1tenth **1/10, 2WD** |
| 모델 | 단일트랙 + **MF6.1 타이어** | 운동학 (→ 3단계) |
| 솔버 | **acados, 80노드 / 33.3Hz / 2.67초** | iLQR, 20노드 / 20Hz / 1.0초 |
| 연산 | AMD Ryzen 5 4600HS (노트북) | Jetson Orin Nano |

> ⚠ **차가 다르다.** 논문 차는 1/8 스케일 4WD 라 하중이동·슬립이 우리보다
> 크다. HyperPM 의 이득은 "미모델링 현상" 이 클수록 커지므로, 우리 차가
> 더 작고 저속이면 이득도 그만큼 작을 수 있다. 논문도 드론 실험에서
> 밧줄 길이 0(=미모델링 없음)이면 개선이 없다고 인정한다.

### 논문 상태 / 입력 (6.4.2, 6.4.4)

```
분석 모델:  x = [v_x, v_y, r]              u = [δ, ω]
MPC 확장:   x = [s, n, μ, v_x, v_y, r, ω, δ]
            u = [ω_ref, δ_ref]             ← 1차 지연 액추에이터 모델
```

`s, n, μ` 는 **Frenet 좌표** (중심선 따라 거리 / 횡오차 / 헤딩차).
비용은 "중심선 진행거리 최대화" + 트랙경계 barrier + 슬립 페널티다.

### HyperPM 신경망 — 아주 작다 (Table 15)

```
GRU hidden size          16
B-spline 제어점           8
MLP features/제어점       32
Δmax                     0.5   ← 파라미터가 공칭값의 50~150% 안에서만 변함
σ_robust                 0.5   ← 학습 시 미래 제어에 주입하는 노이즈
n_reg                    0.2   ← 파라미터 변화량 L1 정규화
```

구조: ① GRU 이력 인코더 → ② B-spline 으로 미래 제어 압축 →
③ **causal masked MLP** (미래가 과거에 영향 못 주게 마스킹) → ④ B-spline 보간.

학습은 **long-horizon rollout** 이다. 한 스텝 예측이 아니라 RK4 로 예측
구간 끝까지 굴려 MSE 를 내고 BPTT 로 역전파한다 (학습 시 0.85s @100Hz,
배포 시 2.67s — B-spline 보간이라 구간을 늘려도 재학습이 필요 없다).

### ★ 중요 — HyperMPC 저장소는 ROS 패키지가 아니다

받아서 바로 돌릴 수 있는 주행 스택이 아니다. 구성은:

```
main.py              학습 스크립트 (PyTorch + wandb)
run_mpc_car.py       시뮬 루프 (acados 솔버)
robot_model/car/     차량 동역학 모델
hyper_prediction_models/   HyperPM 신경망
docker/              Docker 환경
```

- ROS 2 노드 없음, 실차 인터페이스 없음
- **acados** 필요 (C 코드 생성 기반 QP 솔버)
- 상태 9차원: `[s, n, psi, v_x, v_y, r, friction, wheel_speed, delta]`
  — Frenet 좌표계(s, n) + 동역학 + **friction 이 상태에 들어있다**
- **36분 분량의 실주행 데이터**로 학습됨

즉 이 저장소를 쓰려면 우리 쪽에 ① acados 기반 동역학 MPC ② 학습용
주행 데이터 ③ ROS 연동 이 먼저 있어야 한다. 그래서 아래 순서다.

## 2단계 — 실차 검증 + 데이터 수집

**할 일**

1. `docs/CALIBRATION.md` 완료
2. 저속(1.0 → 2.0 m/s) 으로 경로 추종, 횡오차 확인
3. 주행 로그 저장 — 4단계 학습 데이터가 된다

### ★ 데이터 수집 — 지금부터 켜 둘 것

논문은 **36분** 을 모았다. 이건 나중에 몰아서 모으기 어렵다. 어차피
캘리브레이션·튜닝·경로 기록으로 차를 계속 몰게 되므로 **그때마다 켜 둔다.**

```bash
ros2 run mlcs_mpc data_logger --ros-args \
    -p output_dir:=~/mlcs_data -p tag:=cal
```

논문이 기록한 항목(6.4.3)을 그대로 남긴다:

| 분류 | 항목 |
|---|---|
| mocap | `x, y, yaw` + KF 속도 `vx_kf, vy_kf, yaw_rate_kf` |
| 명령 | `cmd_speed, cmd_steer` |
| VESC 내부 | `motor_rpm`, **`motor_iq`(q축 전류)**, `motor_current`, `duty_cycle`, `voltage` |
| 서보 | `servo_position` |

**★ 원본 pose 를 반드시 남긴다.** 논문은 Savitzky-Golay 로 오프라인
미분했고 우리 KF 는 실시간용이라 지연 특성이 다르다. 원본이 있어야
나중에 논문과 같은 방식으로 다시 뽑을 수 있다 — 없으면 필터를 바꿀
때마다 재주행해야 한다.

**시간축은 mocap 스탬프** 다. 여러 센서가 제각각 도착하는데 시간축이
흔들리면 미분이 통째로 오염된다. 안 온 값은 **빈칸**으로 둔다 (0 으로
채우면 "정말 0" 과 구분이 안 된다).

**무엇을 몰아야 하는가** — 논문은 "전문가가 여러 트랙에서, 슬립각과
슬립률의 범위를 바꿔가며 **운용 영역 전체를 덮도록**" 몰았다.
직선만 왕복하면 코너 데이터가 없어서 학습이 안 된다. 가감속·좌우 선회·
한계 부근을 골고루 넣어야 한다.

누적 시간 확인:

```bash
python3 - <<'EOF'
import glob
n = sum(sum(1 for _ in open(f)) - 1 for f in glob.glob('~/mlcs_data/drive_*.csv'.replace('~', __import__('os').path.expanduser('~'))))
print(f'{n} 행 = {n/100/60:.1f} 분  (목표 36분)')
EOF
```

**판정 기준**: 2 m/s 에서 횡오차 평균 10cm 이내

## 3단계 — 동역학 모델

운동학 모델은 타이어가 미끄러지지 않는다고 가정한다. 빨라지면 틀린다.

**바꿀 것**

- `vehicle_model.py` 의 상태를 `[X, Y, psi, v_x, v_y, r, delta]` 로 확장
- Pacejka magic formula 타이어 모델 추가
- `mass`, `lf`, `lr`, `Iz`, 타이어 계수 실측

**이때 acados 가 필요해진다.** 동역학 모델은 iLQR 로도 되지만, 슬립각
제약 같은 하드 제약이 중요해지고 상태가 커져서 SQP 가 유리하다.
`mpc_solver.py` 의 `backend='acados'` 자리가 그것을 위해 비어 있다.

> ★ 저속에서는 운동학 모델이 **더 낫다.** 동역학 모델은 v_x→0 에서
> 슬립각 atan(v_y/v_x) 가 발산한다. 실제로 두 모델을 속도로 전환하는
> 구성이 흔하다.

## 4단계 — HyperPM

**필요한 것**

- 3단계의 동역학 모델 (파라미터를 주입할 대상)
- 2단계에서 모은 주행 데이터 (논문은 36분)
- PyTorch (Jetson 은 NVIDIA 배포 wheel 사용)

**구조**

```
관측 이력 (최근 N 스텝) ─┐
                        ├→ HyperPM (MLP) → 예측구간 각 스텝의 파라미터
계획된 제어 입력 ────────┘                        ↓
                                          MPC 솔버에 주입
```

`mpc_solver.py` 의 `_pvec` 이 스텝마다 달라지는 것이 이 단계의 전부다.
지금은 `self._pvec` 하나를 전 구간에 쓰고 있는데, 그것을 `(N, n_params)`
배열로 바꾸면 된다 — **인터페이스는 이미 그렇게 설계해 뒀다.**

**추론 시간이 관건이다.** 20Hz 안에 신경망 추론 + MPC 풀이가 다 끝나야 한다.
Jetson Orin Nano 에서 작은 MLP 는 1ms 내외일 것이나, 반드시 측정할 것.

## 논문이 밝힌 한계 — 우리도 겪을 것 (6절 Limitations)

### ① 정책 불일치 (policy mismatch) — 가장 큰 문제

데이터는 **사람이 몬 것**인데 배포할 땐 **MPC 가 몬다.** 온라인에서 마주치는
상태-행동 분포가 학습 분포에서 벗어나고, 원 데이터에 과적합되어 폐루프
성능이 떨어진다. 논문도 "온라인 학습으로 완화해야 할 **미해결 문제**" 라고
적었다.

> 이것이 residual 모델이 예측은 1등인데 주행은 진 이유다.

우리 대응: 1단계 운동학 MPC 로 **자율 주행한 데이터도** 함께 모은다.
사람 주행만 있으면 같은 함정에 빠진다.

### ② 미래 제어 궤적의 불확실성

학습 때는 데이터셋의 **정확한** 미래 행동을 쓰지만, 배포 때는 컨트롤러가
내놓는 **예상** 궤적을 쓴다. 논문은 학습 중 B-spline 제어점에 가우시안
노이즈(σ_robust)를 곱해 완화했고, F1TENTH 는 **σ_robust = 0.5** 가 최적이었다
(Table 7: 0.2 는 과적합, 0.5 가 검증 손실 최소).

## 단계를 건너뛰면 생기는 일

| 건너뛰면 | 결과 |
|---|---|
| 캘리브레이션 | 모든 예측이 틀린 채로 게인만 튜닝하게 된다 |
| 운동학 검증 | MPC 문제인지 배관(토픽/좌표계) 문제인지 구분 불가 |
| 데이터 수집 | HyperPM 이 학습할 것이 없다 |
| 동역학 모델 | 시변 파라미터를 **주입할 대상**이 없다 |

HyperMPC 의 이득(19%)은 **동역학 모델이 이미 잘 도는 상태** 에서 그 위에
얹어 얻는 것이다. 기반이 없으면 신경망이 배관 오류를 학습한다.
