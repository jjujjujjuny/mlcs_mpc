# 로드맵 — 여기서 HyperMPC 까지

## 지금 어디까지 와 있나

```
[1단계] 운동학 MPC + mocap 위치추정          ← ★ 지금 여기 (시뮬 검증 완료)
[2단계] 실차 검증 + 파라미터 동정
[3단계] 동역학 모델 (Pacejka 타이어)
[4단계] HyperPM — 시변 파라미터 신경망
[5단계] HyperMPC
```

---

## HyperMPC 가 실제로 무엇인가

논문: [Beyond Constant Parameters: Hyper Prediction Models and HyperMPC](https://arxiv.org/abs/2508.06181)
코드: <https://github.com/hyper-mpc/hypermpc_code>

핵심 아이디어는 **모델 파라미터를 상수가 아니라 시간의 함수로 두는 것**이다.

보통의 MPC 는 예측 구간 전체에서 타이어 마찰 μ, 코너링 강성 같은 값을
하나로 고정한다. 그런데 실제로는 이 값들이 계속 변한다 — 타이어가 데워지고,
하중이 옮겨가고, 노면이 달라진다. HyperPM 은 **신경망이 최근 관측 이력과
계획된 제어 입력을 받아, 예측 구간의 매 스텝마다 다른 파라미터를 내놓는다.**
그 파라미터를 MPC 솔버에 주입한다.

논문 결과: 예측 정확도 62% 개선, 잔차 모델 대비 주행 성능 19% 개선.

### ★ 중요 — HyperMPC 저장소는 ROS 패키지가 아니다

받아서 바로 돌릴 수 있는 주행 스택이 아니다. 구성은:

```
main.py              학습 스크립트 (PyTorch + wandb)
run_mpc_car.py       시뮬 루프 (acados 솔버)
robot_model/car/     차량 동역학 모델
hyper_prediction_models/   HyperPM 신경망
docker/              Docker 환경
```

- ROS 2 노드 없음, 실차 인터페이스 없음
- **acados** 필요 (C 코드 생성 기반 QP 솔버)
- 상태 9차원: `[s, n, psi, v_x, v_y, r, friction, wheel_speed, delta]`
  — Frenet 좌표계(s, n) + 동역학 + **friction 이 상태에 들어있다**
- **36분 분량의 실주행 데이터**로 학습됨

즉 이 저장소를 쓰려면 우리 쪽에 ① acados 기반 동역학 MPC ② 학습용
주행 데이터 ③ ROS 연동 이 먼저 있어야 한다. 그래서 아래 순서다.

## 2단계 — 실차 검증 + 데이터 수집

**할 일**

1. `docs/CALIBRATION.md` 완료
2. 저속(1.0 → 2.0 m/s) 으로 경로 추종, 횡오차 확인
3. 주행 로그 저장 — 4단계 학습 데이터가 된다

**로깅해야 할 것** (HyperPM 학습 입력과 같은 형태로)

```
t, x, y, psi, v_x, v_y, r, delta_cmd, speed_cmd, a_lat
```

mocap 이 v_x, v_y, r 을 다 주므로 별도 센서가 필요 없다 — 이 장비의 이점이다.

> ⚠ 아직 로거 노드는 만들지 않았다. 2단계에 들어갈 때 추가할 것.
> `waypoint_logger.py` 가 비슷한 구조라 그걸 본떠 만들면 된다.

**판정 기준**: 2 m/s 에서 횡오차 평균 10cm 이내

## 3단계 — 동역학 모델

운동학 모델은 타이어가 미끄러지지 않는다고 가정한다. 빨라지면 틀린다.

**바꿀 것**

- `vehicle_model.py` 의 상태를 `[X, Y, psi, v_x, v_y, r, delta]` 로 확장
- Pacejka magic formula 타이어 모델 추가
- `mass`, `lf`, `lr`, `Iz`, 타이어 계수 실측

**이때 acados 가 필요해진다.** 동역학 모델은 iLQR 로도 되지만, 슬립각
제약 같은 하드 제약이 중요해지고 상태가 커져서 SQP 가 유리하다.
`mpc_solver.py` 의 `backend='acados'` 자리가 그것을 위해 비어 있다.

> ★ 저속에서는 운동학 모델이 **더 낫다.** 동역학 모델은 v_x→0 에서
> 슬립각 atan(v_y/v_x) 가 발산한다. 실제로 두 모델을 속도로 전환하는
> 구성이 흔하다.

---

## 4단계 — HyperPM

**필요한 것**

- 3단계의 동역학 모델 (파라미터를 주입할 대상)
- 2단계에서 모은 주행 데이터 (논문은 36분)
- PyTorch (Jetson 은 NVIDIA 배포 wheel 사용)

**구조**

```
관측 이력 (최근 N 스텝) ─┐
                        ├→ HyperPM (MLP) → 예측구간 각 스텝의 파라미터
계획된 제어 입력 ────────┘                        ↓
                                          MPC 솔버에 주입
```

`mpc_solver.py` 의 `_pvec` 이 스텝마다 달라지는 것이 이 단계의 전부다.
지금은 `self._pvec` 하나를 전 구간에 쓰고 있는데, 그것을 `(N, n_params)`
배열로 바꾸면 된다 — **인터페이스는 이미 그렇게 설계해 뒀다.**

**추론 시간이 관건이다.** 20Hz 안에 신경망 추론 + MPC 풀이가 다 끝나야 한다.
Jetson Orin Nano 에서 작은 MLP 는 1ms 내외일 것이나, 반드시 측정할 것.

## 5단계 — 통합

`hypermpc_code` 의 학습 코드를 그대로 쓰되, 학습된 가중치만 가져와
ROS 노드에서 추론한다. 학습은 개발 PC(GPU), 추론은 젯슨.

## 단계를 건너뛰면 생기는 일

| 건너뛰면 | 결과 |
|---|---|
| 캘리브레이션 | 모든 예측이 틀린 채로 게인만 튜닝하게 된다 |
| 운동학 검증 | MPC 문제인지 배관(토픽/좌표계) 문제인지 구분 불가 |
| 데이터 수집 | HyperPM 이 학습할 것이 없다 |
| 동역학 모델 | 시변 파라미터를 **주입할 대상**이 없다 |

HyperMPC 의 이득(19%)은 **동역학 모델이 이미 잘 도는 상태** 에서 그 위에
얹어 얻는 것이다. 기반이 없으면 신경망이 배관 오류를 학습한다.
