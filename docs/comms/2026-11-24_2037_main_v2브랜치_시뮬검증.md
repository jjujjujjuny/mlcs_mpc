## 2. 시뮬 ↔ 실차 검증 (메인 PC, 개루프 재생)

방법
- 11-10 연구실 mocap MPCC 4 주행을 썼다 (v1.5·2.0, 1 s 창 612 개).
- 실제 명령을 도착 시각 (`cmd_recv`) 그대로 v2 `Simulator` 에 넣고, 1 s 뒤 위치를 mocap 과 비교했다.
- 시작 상태는 mocap 의 SG 미분으로 잡았다 (이유는 아래 3 절의 칼만 필터 지연).
- acados 가 없어 폐루프 비교 (랩·횡오차) 는 못 했다.

1 s 뒤 위치 오차

| 시뮬 설정 | v1.5 | v2.0 |
|---|---|---|
| 지금 기본 (조향 1차 지연 τ 0.13) | 7.8 cm · 헤딩 6° | 12.7 cm · 9° |
| 조향 τ 0.04~0.06 | 4.6~4.8 cm | 7.2~8.3 cm |
| 각속도 묶인 서보 (gym 식 3.2~5 rad/s, 지연 ≤ 20 ms) | **5.0~5.2 cm · 3°** | **6.9~7.7 cm · 4.5°** |
| 조향 순수 지연 90 ms 추가 | 더 나쁨 | 19.7 cm · 14° |

- **실제 서보는 τ 0.13 보다 훨씬 빠르다.** MPC 모델 `steering_tau` 도 같은 값이라 MPC 와 시뮬이 함께 틀린다.
- **대회 노트의 '순수 지연 90 ms' 는 서보 지연이 아닐 수 있다.** 조향 명령 → 곡률로 잰 값이라 차체가 도는 시간이 섞여 있다. 연구실 데이터에선 순수 지연을 넣을수록 덜 맞았다.
- 남은 헤딩 치우침: v1.5 에서 +1°, v2.0 에서 +3°.
  - 연구실 바닥에서는 시뮬이 실제보다 조금 더 돈다.
  - 대회장은 반대였다 (조향 ×2.2 가 필요했다) → 바닥마다 다시 맞춰야 한다.
- 종방향은 잘 맞는다: 1 s 뒤 vx ±0.05 m/s. 이 속도 범위에서는 `wheel_model` vesc 와 lag 의 차이가 작다.

## 3. 실차 비동기 경로 실측 (같은 로그의 stamp · recv · cmd_recv · solve_ms)

| 단계 | 실차 | 지금 시뮬 |
|---|---|---|
| mocap | 10 ms (p95 12), 전달 3 ms (p95 7) | 정확히 10 ms, 전달 0 |
| **mocap_bridge 칼만 필터** | **vx·r 이 80~90 ms 늦다**, 코너에서 가짜 vy 평균 −0.22 m/s | 참값 그대로 |
| 제어 | 30 Hz, 풀이 24 ms (p95 26, 최대 64), /drive 간격 p99 83~98 ms (pending 이면 그 주기를 건너뜀) | main.py: 정확히 30 Hz, 풀이 0 (`--delay` 를 줘야 반영) |
| VESC | 50 Hz | sim_node 50 Hz |

- **가짜 vy 의 원인**
  - 칼만 필터가 x·y·yaw 를 따로 거르고, 늦은 전역 속도를 현재 yaw 로 돌린다.
  - 그래서 코너에서 MPC 가 '바깥으로 미끄러진다' 고 본다.
  - 시뮬 튜닝 때는 이 효과가 없다.
- **상태를 잰 순간 → 명령까지 실차는 약 30~35 ms 다.** main.py 기본은 0 이다.
