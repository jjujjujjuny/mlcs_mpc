# docs/comms — 메인 PC 클로드 ↔ 젯슨 클로드 소통 창구

대회장에서는 화면 공유로 복사·붙여넣기를 하기 어렵습니다. 그래서 두 클로드가 이 폴더에 메시지 파일을 남기고 git으로 주고받습니다. 사람(사용자)도 같은 방식으로 씁니다.

## 규칙

1. **메시지 하나에 파일 하나.** 이름은 `YYYY-MM-DD_HHMM_<보낸이>_<주제>.md` 로 합니다.
   - 보낸이는 `main`(메인 PC 클로드), `jetson`(젯슨 클로드), `user`(사람) 중 하나입니다.
   - 예: `2026-11-14_1030_jetson_연습1_로그.md`
   - 파일이 따로라서 서로 동시에 써도 git 충돌이 나지 않습니다.
2. **남의 메시지는 고치지 않습니다.** 답은 새 파일로 쓰고, 첫머리에 `답: <원래 파일 이름>` 을 적습니다.
3. **첫머리 형식**

   ```
   보낸이: jetson   받는이: main   답: (없으면 -)
   요청: <받는 쪽이 할 일 한 줄 — 없으면 "참고">
   급함: 예/아니오 (다음 세션 전에 필요하면 예)
   ```

   그 아래에 본문을 씁니다. 결론을 맨 위에 두고, 숫자는 표로 정리합니다. 한국어로 씁니다.
4. **데이터는 여기 넣지 않습니다.** 로그와 맵은 지금처럼 `data/runs/runs_<날짜>_<세션>.tar.gz` (MANIFEST.txt 포함) 로 올리고, 메시지에는 묶음 이름만 적습니다.
5. **보내는 법:** 그 파일 하나만 커밋하고 푸시합니다. 다른 변경분까지 같이 쓸려 들어가지 않게, 파일 이름을 지정해서 `git add` 합니다.

   ```
   git pull --rebase --autostash
   git add docs/comms/<파일> && git commit -m "comms: <주제>" && git push
   ```

6. **받는 법:** 작업을 시작할 때, 그리고 사람이 "comms 확인해" 라고 하면 `git pull` 하고 이 폴더에서 새 파일을 읽습니다.
   - 읽었다는 표시는 답장 파일로 합니다. 처리가 오래 걸리면 "받음, ~시까지" 한 줄만이라도 먼저 보냅니다.
7. **담당 구역** — 상대 구역의 파일은 직접 고치지 않고, 메시지로 후보값이나 패치를 제안합니다.

   | 담당 | 구역 |
   |---|---|
   | 젯슨 | `src/` (노드, `config/*.yaml`, race.yaml, hmpc.yaml), `drive.sh`, `race.sh`, 맵과 트랙 생성, 실차 실행 |
   | 메인 PC | `hypermpc/hpm/` 학습, `tools/venue_*.py`, `docs/notes/` 분석 노트 |

   설정을 실제로 바꿀지는 젯슨과 사람이 정합니다.
8. **비밀 정보 금지:** API 키, 비밀번호, 토큰은 쓰지 않습니다.

## 대회장 흐름 (토·일)

```
젯슨/사람: 연습 주행·맵핑 → data/runs/runs_<날짜>_<세션>.tar.gz + MANIFEST (설정, 사건 메모, 시작 전압)
           → docs/comms/..._jetson_<세션>.md "올림, 분석 요청"  → push
메인 PC  : git pull → ~/hpm-venv/bin/python tools/venue_intake.py   (1분: 랩타임·벽 여유·해석시간·마찰·지연·모델오차)
           → 판단 → docs/comms/..._main_<세션>_분석.md (+ 필요하면 docs/notes/)  → push
젯슨     : pull → 읽고 적용할지 결정 (오프라인 시험은 젯슨에서) → 결과를 답장
```

MANIFEST 주행 줄은 `<YYYYMMDD_HHMMSS>  <트랙이름> ...` 형식으로 써 주세요. `venue_intake.py` 가 이 줄에서 트랙을 찾아 랩타임과 벽 여유를 계산합니다(기존 MANIFEST와 같은 형식).
