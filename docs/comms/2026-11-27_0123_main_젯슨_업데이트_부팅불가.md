## 결론
11-26 12:40 에 젯슨에서 업데이트를 돌렸는데, **패키지를 푸는 단계(unpack) 도중 136 번째 패키지(packagekit)에서 끊겼다.** 설정 단계(`Setting up ...`)는 한 번도 실행되지 않았다.
그래서 새 커널 5.15.199-tegra 의 파일만 깔리고 initrd 생성·부팅 설정·모듈 등록이 모두 빠졌다. 지금 부팅하면 UEFI 다음에 검은 화면이 되고 네트워크에도 나타나지 않는다.
**하드웨어와 펌웨어는 정상이다.** UEFI 메뉴가 뜨고 NVMe 도 인식된다. 고장이 아니라 업데이트가 반쯤 된 상태라서, `dpkg --configure -a` 로 마무리하면 살아날 가능성이 높다.

## 할 일 (순서대로)

### 0. 디스크 찾기 — 노트북 자기 디스크와 헷갈리지 말 것
```
lsblk -o NAME,SIZE,MODEL,PARTLABEL,LABEL,FSTYPE
```
SN5000 465 GB 쪽에서 PARTLABEL `APP` 인 ext4 파티션이 루트다 (보통 `sdX1`). 아래에서는 `/dev/sdX1` 로 쓴다.

### 1. 백업 (수리 전에 반드시)
```
sudo mkdir -p /mnt/jet && sudo mount /dev/sdX1 /mnt/jet
mkdir -p ~/jetson_backup_20261127
sudo rsync -aHAX /mnt/jet/home/mlcs/ ~/jetson_backup_20261127/home_mlcs/
sudo cp -a /mnt/jet/var/log/apt ~/jetson_backup_20261127/
```
- `~/mlcs_mpc` 에 푸시 안 된 커밋이나 변경이 있는지 본다:
  `git -c safe.directory='*' -C /mnt/jet/home/mlcs/mlcs_mpc status -sb` 와 `log origin/main..`
- 있으면 사용자에게 알린다.
- `/mnt/jet/boot/extlinux/extlinux.conf` 전체와 `history.log` 마지막 `Start-Date`/`Commandline` 블록을 확인한다. 무엇으로 업데이트를 시작했는지 볼 수 있다.

### 2. arm64 chroot 준비 (노트북은 x86)
```
sudo apt install -y qemu-user-static binfmt-support
for d in dev dev/pts proc sys; do sudo mount --bind /$d /mnt/jet/$d; done
sudo mount -t tmpfs tmpfs /mnt/jet/run
sudo mkdir -p /mnt/jet/run/systemd/resolve
sudo cp /etc/resolv.conf /mnt/jet/run/systemd/resolve/stub-resolv.conf   # chroot 안 DNS
sudo chroot /mnt/jet uname -m     # aarch64 가 나와야 한다
```

### 3. 마무리 (chroot 안)
```
sudo chroot /mnt/jet /bin/bash
dpkg --audit                      # 반쯤 된 패키지 목록 — 로그로 남겨 둘 것
dpkg --configure -a
apt -f install
apt update && apt upgrade         # 137 번 이후 못 깔린 나머지 패키지
```
- **initrd 확인:** `ls /boot` 에 `initrd.img-5.15.199-tegra` 가 생겼는지 본다. 없으면 직접 만든다:
  `update-initramfs -c -k 5.15.199-tegra` → `nv-update-initrd` (이걸로 `/boot/initrd` 가 갱신된다).
- **extlinux 확인:** `/boot/extlinux/extlinux.conf` 의 primary 항목이 `/boot/Image`, `/boot/initrd` 를 가리키고, FDT 줄이 있다면 그 dtb 파일이 실제로 있는지 확인한다.
- **★ NVIDIA 패키지 주의:** `nvidia-l4t-*`, 특히 bootloader·kernel 계열의 postinst 는 `/proc/device-tree` 로 보드를 판별한다. 노트북 chroot 에서는 보드 정보가 없어서 실패하거나 엉뚱한 보드로 잡힐 수 있다.
  - 실패하면 **억지로 넘기지 말고**(`--force-*` 금지, QSPI 펌웨어 캡슐을 잘못 쓰면 더 나빠진다) 패키지 이름과 오류를 기록한다.
  - 일반 우분투 패키지만 먼저 끝내고, NVIDIA 쪽은 젯슨이 부팅된 뒤 실기기에서 `sudo dpkg --configure -a` 로 마무리한다.
  - 다만 부팅에 꼭 필요한 initrd 와 extlinux 는 위처럼 손으로라도 맞춰 둔다.

### 4. 정리하고 젯슨에 다시 꽂기
```
exit
sudo umount /mnt/jet/run /mnt/jet/dev/pts /mnt/jet/dev /mnt/jet/proc /mnt/jet/sys
sync && sudo umount /mnt/jet
```
- SSD 를 젯슨에 다시 꽂는다. 유선 랜은 공유기에 연결해 둔다.
- 1~2 분 뒤 `./car.sh find` 로 찾는다. 공유기 대역에서 안 보이면 유선 고정 IP 192.168.0.15 도 확인한다 (노트북에 192.168.0.x 주소 임시 추가).
- 부팅되면 SSH 로 들어가서:
  - `sudo dpkg --configure -a && sudo apt -f install`
  - `uname -r` 이 `5.15.199-tegra` 인지
  - 디스플레이·와이파이·유선이 되는지
  - `lsmod | grep nvgpu`

- 재플래시하면 `~/mlcs_mpc` 환경을 SETUP_JETSON.md 순서대로 다시 구축해야 한다.
