## D 기준선 해석 (동의)

- **H** 는 두 시험 차(H+70 ms, H″+15 ms) 어디서나 무난합니다. 벽 밖 0~4 % 입니다.
- **H″** 는 자기 시험 차에서만 이득이 있고, 그것도 주로 1111_5 진행 +7.6 % (빨라짐) 입니다. 차가 H 에 가까우면 벽 밖이 +4~5 %p 늘어납니다.
- 1 s 예측과 지연 분석으로는 실제 차가 H″ 쪽에 가깝지만, 오프라인 시험만으로는 확정할 수 없습니다. 실차 ABAB 로 정합니다.
- 기본값은 **H 유지** 입니다. H″ 는 아래 기준을 모두 넘을 때만 채택합니다.

## 진행

1. 낮은 v_max (예: 3.0) 에서 H·0.36 과 H″·0.41 을 A B A B 로 달립니다. 각 1.5~2 분입니다.
2. 여기서 통과하면 같은 방식으로 v_max 4.8 에서 한 번 더 합니다.
3. 도중에 H″ 가 벽에 닿거나 사람이 개입해야 하면 그 자리에서 중단하고 H 로 돌아갑니다.

## H″ 채택 기준 (같은 트랙, 같은 v_max 의 A 와 B 평균 비교)

| 지표 (`tools/venue_intake.py`) | 조건 |
|---|---|
| 랩타임 (정상 랩 중앙값) | H″ 가 2 % 이상 빠름 |
| 벽 닿음 비율 (차 중심에서 벽까지 여유 < 0.15 m) | H 보다 늘지 않음 (+0.5 %p 이내) |
| 벽까지 최소 여유 | H 보다 5 cm 넘게 줄지 않음 |
| 교착 후진 횟수 | H 보다 늘지 않음 |
| 풀이 시간 p99 | H 보다 5 ms 넘게 늘지 않음 |
| 사람 개입 / 벽 충돌 | 0 |

- 하나라도 어기면 H 를 유지합니다.
- 랩타임만 못 넘고 나머지는 같으면, 이득이 없는 것이므로 역시 H 를 유지합니다.
- H″·0.41 이 나쁘게 나오면, 원인을 가르기 위해 H″·0.36 을 A/B 한 쌍 더 달려 주세요.

## 로그 올리는 형식

- 묶음: `data/runs/runs_<날짜>_ABAB.tar.gz`, 안에 MANIFEST.txt 를 넣습니다.
- MANIFEST 주행 줄 형식:

  ```
  <YYYYMMDD_HHMMSS>  <트랙>  <v_max>  <friction>  <모델 H|H″>  <A|B>  <메모: 개입·벽 닿음 시각, 시작 전압>
  ```

- wheel_odom 을 켜고 기록해 주세요. 마찰 최적값도 같이 다시 보겠습니다.
- 올린 뒤에는 `..._jetson_ABAB_올림.md` 를 보내 주세요.
