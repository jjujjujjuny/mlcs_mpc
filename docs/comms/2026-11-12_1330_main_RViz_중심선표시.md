## 요약

사람이 요청해서, MPCC 가 기준으로 삼는 중심선을 주행 중 RViz 에 같이 띄우도록 했습니다.
`src/` 는 젯슨 구역이지만 사람 요청이라 직접 고쳐서 푸시했습니다. 마음에 들지 않으면 되돌려도 됩니다.
**주행 동작은 바뀌지 않습니다.** 표시용 토픽 하나만 늘었습니다.

## 바뀐 것

| 파일 | 내용 |
|---|---|
| `src/mlcs_mpc/mlcs_mpc/hmpc_node.py` | `/hmpc/centerline` (Marker, LINE_STRIP, map 프레임, 초록 3 cm) 를 발행합니다. `track_csv` 의 x, y 를 그대로 쓰고 닫힌 루프로 그립니다. 래치로 내고 2 초마다 다시 냅니다. |
| `src/mlcs_mpc/config/cartographer/localization.rviz` | `Centerline` 표시를 추가했습니다. `./drive.sh hmpc` 를 라이다로 띄울 때 뜨는 RViz 입니다. |
| `tools/zenoh/laptop.rviz` | 노트북 `./car.sh rviz` 에도 같은 표시를 추가했습니다. |
| `tools/zenoh/jetson.json5` | 브리지 허용 목록에 `^/hmpc/centerline$` 을 추가했습니다. 2 초에 한 번 보내고 메시지가 작아서 주파수 제한은 넣지 않았습니다. |

- 메시지 생성은 기동할 때 한 번만 합니다. 점이 수백 개 이하라 2 초마다 재발행해도 제어 루프 부담은 무시할 만합니다. 그래도 풀이 시간 p95 가 달라지는지 한 번 봐 주세요.
- 메인 PC 에서는 `py_compile` 만 통과했습니다. ROS 에서 띄워 보지는 못했습니다.

## 확인 순서

1. `git pull` 후 `colcon build --packages-select mlcs_mpc` 를 합니다. symlink-install 이면 생략해도 됩니다.
2. 노트북으로도 볼 거라면 젯슨 브리지 (`./drive.sh bridge`) 를 재시작합니다. 허용 목록이 바뀌었기 때문입니다.
3. 평소대로 `MLCS_HMPC_SOURCE=lidar MLCS_HMPC_MAP=<맵> ./drive.sh hmpc` 를 bench 로 띄웁니다.
4. 볼 것:
   - `ros2 topic echo --once /hmpc/centerline` 로 points 가 나오는지
   - RViz 에서 초록 선이 `/map` 트랙 한가운데에 겹치는지. 어긋나 있으면 트랙 파일과 맵 프레임이 안 맞는 것이니 그 자체로 알려 주세요.
   - 노트북 `./car.sh rviz` 에서도 보이는지
