## ① 상태 추정: vx = 바퀴 속도, r = 자이로 (서용화 연구원님 결정, 11-25)

- 이유: mocap_bridge 칼만 필터 때문에 vx·r 이 80~90 ms 늦다 (11-10 실측, 클라우드·메인 PC 같은 값). 상태 추정이 너무 느리다.
- 제안 (lidar_bridge 에 이미 있는 것과 같게 — af48e21 의 자이로 r):
  - **r** = wheel_odom `/odometry/filtered` 의 바이어스 뺀 자이로. 0.1 s 넘게 끊기면 KF r 로 (lidar_bridge 의 gyro_rate / gyro_timeout 그대로)
  - **vx** = `/sensors/core` erpm ÷ 4781.5 × **1.044** (실측 환산 오차). 끊기면 KF vx
  - 위치·yaw 는 mocap KF 그대로
- 시뮬 (v2 `main.py --realtime`, 제어 시점의 오차 rms)

| 추정 | vx | vy | r |
|---|---|---|---|
| 지금 (kf) | 0.089 | 0.309 | 0.429 |
| vx 바퀴·r 자이로 (gyro) | 0.093 | 0.309 | **0.174** |
| gyro + 아래 ② vy | 0.093 | **0.117** | 0.174 |

  - r 은 크게 좋아진다.
  - vx 는 거의 같다. 바퀴 속도는 가감속 미끄럼만큼 틀리고, KF 는 늦어서 틀리기 때문이다.
  - 주행 로그에 바퀴 속도와 KF vx 를 둘 다 남겨 주면 실차에서도 비교할 수 있다.

## ② vy: 늦은 전역 속도를 '지금 yaw' 로 돌리지 말고 '그만큼 늦은 yaw' 로

- 지금 `mocap_bridge._pose_cb` 는 80~90 ms 늦은 전역 속도 (vx_g, vy_g) 를 지금 KF yaw 로 돌린다.
- 그래서 코너에서 vy 가 안쪽으로 치우친다 (가짜 미끄러짐).
- **11-10 실제 로그 4 주행으로 확인했다.** 로그의 vx_kf·vy_kf·yaw 로 전역 속도를 되살려 다시 돌렸고, 정답은 위치 SG 미분 뒤축 vy 다.

| vy | 오차 rms (m/s) | 코너 (\|r\|>1) 치우침 |
|---|---|---|
| 지금 | 0.18 ~ 0.26 | −0.22 ~ −0.30 |
| 그냥 0 | 0.04 ~ 0.08 | — |
| **yaw − r·0.10 로 돌림** | **0.03 ~ 0.04** | ±0.04 |

  - 실제 뒤축 vy 는 rms 0.04~0.08 로 작다. 지금 값의 오차는 그 3~5 배다 → MPC 가 코너마다 '밖으로 미끄러진다' 고 본다.
- 수정안 (두 줄):

```python
a = fyaw - yaw_rate * 0.10          # 속도가 늦은 만큼 yaw 도 되돌린다 (①을 하면 yaw_rate 는 자이로 값)
lateral = -vx_g * math.sin(a) + vy_g * math.cos(a)
```

  - speed 는 그대로 둬도 된다 (cos 라 영향 작음). 0.10 은 파라미터 `vy_lag` 로 빼 두면 좋겠다.

## ③ κ·벽을 한 스테이지 뒤에서 읽는다 — 확인됨 (클라우드 의심이 맞음)

- **main `hmpc_node.py` 685 행**: `s = s_pred + (x[0] + s_shift − s_pred[1])`
  - `ocp_worker` 가 돌려주는 `s_pred` 는 그 풀이의 스테이지 0~N 그대로다 (`xs[:, 0]`, 당기지 않음).
  - 그래서 `s[1] = x0` 가 된다.
  - 새 풀이의 스테이지 k 는 지금부터 k−1 칸 뒤 위치에서 κ·벽을 읽는다. 4.8 m/s 에서 약 16 cm 뒤다.
  - 상대 차 쪽은 이미 `s_now = s[1:]` 로 한 칸 당기고 있다. 같은 이유다.
- **v2 (mpcc-v2)** 의 `control/mpcc_node.py` 550 행·`env/mpc/mpcc.py`·`offline.py` 도 벽을 `s_pred` 그대로 읽는다.
  - κ 는 v2 에서 상태 s 로 읽어서 괜찮다. 벽만 한 칸 늦다.
- 수정안 (main 기준):

```python
sp = np.r_[self.s_pred[1:], 2 * self.s_pred[-1] - self.s_pred[-2]]
s = sp + (x[0] + s_shift - sp[0])       # s[0] = 지금 위치
...
s_now = s                               # 상대 차 쪽 한 칸 당김은 이제 필요 없다
```

  - 코너 진입 κ 를 16 cm 늦게 보던 것이 조향 배율 (×1.1→×2.2) 에 섞였을 가능성도 있다 (확인 안 함).
  - 고치면 조향 맵·여유를 다시 봐야 할 수 있다 → 연구실 mocap 에서 ABAB.

## ④ 거치대 계단 응답 2 가지

1. **서보** (지난 부탁 그대로): 명령 0 → ±0.2 → ±0.4, servo_position + 영상 또는 mocap. 최대 각속도·순수 지연.
   - 개루프 재생은 τ 0.03 (지연 0~15 ms) 이 가장 맞았다.
   - 연구실 1 s 위치 오차 τ 0.13 10.3 cm → 0.03 5.1 cm.
   - **대회장 라이다 11-15 (최고 6 m/s)** 에서도 같은 방향이다: f0.7 에서 42 → 33 cm, 모든 속도 구간. 순수 지연 50 ms 는 나빠졌다.
2. **바퀴 (새 VESC PID)**: 11-24 설정은 속도 PID ki 0.002 → 0.0002 (1/10), kp·kd 도 바뀌었다.
   - 바퀴 τ 0.4 는 11-08 설정에서 잰 값이다.
   - `actuator_id` 로 속도 계단 (0 → 1.5 → 3 → 1.5 → 0 m/s) 을 한 번 다시 재 주면, 시뮬 VESC 모델과 MPC `wheel_speed_tau` 를 맞춘다.
