요청: **주행 전마다 자이로 바이어스 확인** (지금 바로). 그리고 wheel_odom 바이어스 초기화 수정 검토.
급함: **예 — 예선·결승 전**

## 무엇이 있었나

**140246 (연습 4 마지막, v2.5, "코너 헤딩 중앙 21° 로 가장 큼") 은 주행 내내 자이로가 −1.27 rad/s (−73 °/s) 틀려 있었습니다.**

| 주행 | 자이로 − 라이다 회전 (10 s 구간별, rad/s) | 정지 중 자이로 r |
|---|---|---|
| 다른 대회장 주행 24 개 | 대부분 \|·\| < 0.01 (위치 튐 구간만 ±0.1~0.3) | 0.000 |
| **140246** | **−1.27 ~ −1.28 (11 구간 전부, 처음부터 끝까지)** | **−1.344** |

- 명령 조향 0 일 때 곡률: 라이다 −0.06 1/m, 자이로 **−0.67 1/m**. 다른 주행은 둘이 같습니다.
- lidar_bridge 는 MPC 요레이트로 자이로를 씁니다 (`gyro_rate: True`). 그래서 이 주행 내내 **MPC 는 차가 오른쪽으로 1.3 rad/s 돌고 있다고 믿었습니다.** 큰 헤딩·안쪽 벽 붙음의 일부가 이것일 수 있습니다.
- venue_check 연습 4 의 이상한 숫자 (오차 0.17~0.24, 회전 편향 −0.3~−0.55) 도 대부분 이 주행 탓입니다 (주행별 1 s 오차: 140246 중앙 0.36, 나머지 0.006~0.03).

## 원인 (wheel_odom.py `_imu_cb`)

```python
if self.t_last is None:
    self.t_last = t
    self.bias = r_raw            # ← 첫 샘플 하나로 바이어스를 정함
...
if abs(self.v_wheel) < 0.02 and abs(r_raw - self.bias) < self.bias_gate:   # gate 2 °/s
    self.bias += ...             # ← 첫 값이 틀리면 정지 중 (r_raw≈0) 과 차이가 73 °/s 라 영원히 갱신 안 됨
```

- wheel_odom 이 뜰 때 첫 IMU 샘플이 차를 들거나 돌리는 중이었거나, 한 번 튄 값이었으면 바이어스가 그 값 (+1.34 rad/s) 으로 고정되고, gate 때문에 다시는 고쳐지지 않습니다.

## 지금 할 것 (코드 수정 없이)

1. **매 주행 출발 전, 차를 세워 둔 채** wheel_odom 로그의 바이어스 출력 (`math.degrees(self.bias)`, 123 행 근처 보고) 이 **±2 °/s 안**인지 봅니다. 또는 `ros2 topic echo /odometry/filtered --field twist.twist.angular.z` 가 0 근처인지.
2. 아니면 **wheel_odom 만 다시 띄우거나 주행 명령을 다시 시작**합니다. 다시 띄울 때 차를 만지지 마세요.
3. 점검표에 한 줄: "출발 전 정지 상태 요레이트 0 확인".

## 코드 수정 제안 (젯슨 판단, 짧음)

- 첫 샘플 대신 **정지 중 처음 1 s 의 중앙값**으로 바이어스를 잡기, 그리고
- 정지 (|v_wheel| < 0.02) 인데 \|r_raw − bias\| > gate 가 **2 s 넘게** 이어지면 바이어스를 r_raw 로 다시 잡기 (손으로 돌리는 시험은 2 s 안에 끝나므로 기존 대책과 충돌 적음).
- 또는 lidar_bridge 쪽 안전망: 자이로 r 과 KF r 의 3 s 평균 차가 0.3 rad/s 넘으면 KF 로 바꾸고 경고 (지금은 끊김일 때만 KF).
