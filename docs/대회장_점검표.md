# 대회장 점검표 (비행기 운반 후)

차를 위탁수화물로 보내고 배터리는 따로 들고 갔다가 대회장에서 다시 조립하는 경우의 점검 순서입니다. mocap 이 없으니 조향·속도 확인은 **자이로·바퀴 속도·라이다**로 합니다.

원칙
- **위에서 아래로, 한 단계씩.** 앞 단계가 통과해야 다음으로 갑니다. 처음 자율주행은 v_max 1.0 부터 시작합니다.
- **통과 기준은 숫자로 확인합니다.** 눈으로 "괜찮아 보임" 은 통과가 아닙니다.
- 이상하면 그 자리에서 사진과 로그를 남기고 `docs/comms/` 로 메인 PC 에 보냅니다.
- 기준값은 11-11 로비 주행과 11-07~11-10 실측에서 온 값입니다.

---

## 0. 출발 전 (짐 쌀 때)

- [ ] 배터리 단자 절연 테이프, 기내 반입 규정 확인 (리튬 배터리는 위탁 불가)
- [ ] 예비품: 서보 혼·서보 세이버, 휠 너트, 육각렌치 세트, 케이블 타이, 절연 테이프, 이더넷 케이블 (라이다), USB 케이블 (VESC), 조이스틱 동글·충전 케이블
- [ ] 노트북 저장소 `git pull` 최신 (젯슨과 같은 커밋), 제어판 동작 확인
- [ ] 젯슨 `git status` 깨끗한지, `git log -1` 커밋 번호 적어 두기
- [ ] 젯슨 기준 사진 찍기: 위, 앞, 옆, 라이다 장착부, 조향 링크 (도착 뒤 비교용)

## 1. 도착 — 전원 넣기 전 (기계)

- [ ] 외관: 섀시 금, 범퍼, 바퀴 휨, 타이어 이물·마모
- [ ] **라이다 장착**: 나사 풀림, 앞을 똑바로 보는지 (출발 전 사진과 비교). 돌아가 있으면 위치추정 전체가 틀어진다
- [ ] 조향: 손으로 좌우 끝까지 돌려 걸림·유격 없는지, 서보 혼 나사, 서보 세이버 스프링
- [ ] 바퀴를 손으로 굴려 걸림 없는지, 너트 조임
- [ ] 커넥터 다시 꽂기: VESC ↔ 모터 3상, VESC USB, 라이다 이더넷·전원, 젯슨 전원
- [ ] 배터리 결합 전 극성 확인 → 결합 → **전압 기록** (완충 3S 약 12.6 V. 11-11 은 11.5 V 근처 출발)

## 2. 전원 켠 뒤 — 소프트웨어·통신

| 확인 | 명령 | 통과 기준 |
|---|---|---|
| 젯슨 부팅·접속 | 노트북 `./car.sh find` → SSH | 접속됨 (`yax_5G` 에서 192.168.50.x) |
| 시계 | 노트북 `./car.sh clock` | 차이 0.1 s 이내. 젯슨이 1970 이면 기록 이름만 1970 이 된다 (주행엔 영향 없음) |
| 저장소 | `cd ~/mlcs_mpc && git log -1` | 출발 전 적은 커밋과 같음 |
| 노드 안전 시험 | `python3 tools/test_hmpc_node.py` | `모두 통과` (약 10 분) |
| 라이다 | `./drive.sh lidar --norviz` | 주기 약 40 Hz, 앞쪽 벽까지 거리가 실제와 맞음 |
| VESC | `./drive.sh bench` (bringup) 로그 | `Connected to VESC with firmware version 7.0` |
| 조이스틱 | `./drive.sh joy` | 스틱 좌우·스로틀 반응, **LB (수동↔자율), B (출발)** 동작 |
| 제어판 | 노트북 `./car.sh panel` | 상태 칩, 배터리 전압 보임 |

- [ ] **비상 정지 먼저 확인**: 차를 들어 바퀴가 뜬 상태에서 자율 출발(B) → LB 로 수동 전환 → 바퀴가 바로 서는지. 이게 안 되면 아래 단계로 가지 않는다

## 3. 센서 점검 (차를 바닥에, 모터 꺼진 상태로도 가능)

띄우는 법: 터미널 1 `./drive.sh joy` (VESC·조이스틱), 터미널 2 `source ~/f1tenth_ws/install/setup.bash && ros2 run mlcs_mpc wheel_odom`.
`wheel_odom` 이 5 초마다 `yaw ±…°` 를 찍는다. 거리는 `ros2 topic echo /odometry/filtered --field pose.pose.position`.

- [ ] **자이로 부호·크기**: 차를 바닥에 둔 채 반시계로 정확히 90° 돌린다 (바닥 선·벽 모서리에 맞춰서)
  - 통과: **+85 ~ +95°** (11-11 실측 +89.2°). 부호가 반대면 장착이 뒤집힌 것 — `gyro_sign` 확인
  - 정지 바이어스 ±0.5°/s 이내, 멈춘 뒤 흐름 0.1° 미만
- [ ] **바퀴 속도 배율**: 줄자로 직선 3 m 를 표시하고 조이스틱으로 천천히 달려서 `odom_x/y` 거리와 비교
  - 통과: 3 m 에서 ±10 cm (vx_scale 1.042 가 맞으면)

## 4. 조향 점검 (mocap 대신 자이로로 — `tools/steer_check.py`)

`./drive.sh cal` 은 mocap 이 필요해서 대회장에서는 못 쓴다. rally 모드 (스틱 끝 = 고정 속도·고정 조향, 십자키로 조절) 와 점검 도구를 같이 띄운다.

```
터미널 1   ./drive.sh rally
터미널 2   ./drive.sh steercheck
```

1. 차를 세워 둔 채 "✓ 자이로 바이어스" 가 뜰 때까지 (3 초)
2. **중립**: 스틱 좌우를 놓고 직선 0.8~1.5 m/s 로 3~4 m, 두세 번
3. **조향 끝**: 십자키로 최대 조향 0.40 → 스틱 왼쪽 끝으로 원 한두 바퀴, 오른쪽 끝으로 한두 바퀴 (0.5~1.0 m/s)
4. Ctrl+C → 요약

- [ ] 중립 곡률 |κ| ≤ 0.025 1/m. 넘으면 도구가 `steering_angle_to_servo_offset` 새 값을 알려 준다 (지금 0.5077) → vesc.yaml 고치고 브링업 다시 → 한 번 더
- [ ] 최대 조향 반경 좌우 **0.78 ~ 0.89 m** (모델 0.83 m), 좌우 차이 10 % 이내. 중립을 고친 뒤에도 한쪽만 크면 서보 혼이 밀렸거나 링크가 휜 것
- [ ] 끝까지 꺾은 채 서보에서 '지잉' 소리가 계속 나면 기계 한계에 닿은 것 → `./drive.sh servo` 로 한계를 다시 재고 `max_steer` 확인
- **연구실 기준값 (11-12 출발 전, `steercheck_20261112_134411.csv`)** — 대회장 값과 비교:

  | | 곡률 1/m | 반경 | 모델 |
  |---|---|---|---|
  | 중립 (명령 0) | −0.023 (오른쪽으로 4 m 에 5°) | — | 0 |
  | 최대 왼쪽 (+0.40) | +1.204 | 0.83 m | 0.83 m |
  | 최대 오른쪽 (−0.40) | −1.178 | 0.85 m | 0.83 m |

  대회장에서 중립이 이보다 0.02 넘게 달라지거나 반경이 5 cm 넘게 달라지면 운반 중 조향이 틀어진 것
- 가짜 메시지 시험: 중립 0.02 rad 틀어짐 → +1.11° 로 잡고 offset 0.5077 → 0.5248 권장 (정답 0.5254)

## 5. 위치추정 점검 (라이다)

- [ ] **맵핑**: 트랙을 비운 상태에서 제어판 → 맵핑 시작 → 조이스틱으로 1~2 바퀴 → 맵 저장 → 정지
- [ ] **트랙 만들기**: 제어판 → 트랙 만들기. 경고가 나와도 저장된다 (기준 미달 표시 확인)
  - **가장 급한 코너 확인**: 차 최소 회전 반경 0.83 m + 벽 여유 0.28 m 를 감당하는지 그림 (`map_track.png`) 으로 본다. 1111_3 헤어핀처럼 좁으면 그 코너에서 교착이 난다
- [ ] **라이다 장착 yaw**: 위치추정으로 긴 직선을 똑바로 달린 로그에서 `vy_kf` 평균이 거의 0 인지 (장착이 돌아가 있으면 직선에서도 옆으로 미끄러지는 것처럼 나온다)
- [ ] **맵 고정**: `hmpc` 로그의 "맵 고정: 보정 … cm, 맞춤 비율 …" — 비율 **0.9 이상**, 보정이 수십 cm 로 계속 커지지 않을 것. "보정 되돌림" 이 가끔 나오는 건 정상
- [ ] RViz: 초록 중심선 (`/hmpc/centerline`) 이 맵 트랙 가운데에 겹치는지, 스캔이 벽에 붙는지

## 6. 헛것 목록 (상대 차 결승용)

- [ ] 트랙에 **상대 차·사람 없이** `obstacles: learn` 으로 2~3 바퀴 → 끝나면 `maps/<맵>_ghost.csv` 자동 갱신
- [ ] 그다음 `obstacles: watch` 로 1 바퀴: 빈 트랙에서 장애물 발행이 거의 0 인지 (`hmpc` 로그 "장애물 발행 N번")

## 7. 주행 단계 올리기

| 단계 | 설정 | 통과 기준 |
|---|---|---|
| ① bench | `drive: false` | 조향만 움직이고 바퀴 0, 풀이 p95 25 ms 이하 |
| ② 저속 | v_max 1.0, `obstacles: off` | 한 바퀴 이상, 벽 안 닿음, 교착 없음 |
| ③ 중속 | v_max 2.0 → 3.0 | 랩 3개 이상 깨끗, 벽 여유선 넘음 2 % 이하 |
| ④ 고속 | v_max 4.0 → 4.8 | 위와 같음. 랩이 오히려 느려지면 그 아래로 |
| ⑤ 결승 준비 | `obstacles: lidar` (상대 차 있으면) | 상대를 임시 벽으로 비켜 지나감 |

- 각 단계 로그는 `data/runs/runs_<날짜>_<세션>.tar.gz` + MANIFEST 로 올리고 `docs/comms/` 에 "올림, 분석 요청"
- 시간이 남으면 H″ ABAB: `race.yaml` 주석 세 줄 풀고 friction 0.41 (기준: `docs/comms/2026-11-12_1325_main_ABAB_판정기준.md`)

## 8. 대회 직전

- [ ] **젯슨 정리**: VS Code·크롬·RViz 를 닫는다 — 제어판 '젯슨 정리' 또는 `./drive.sh quiet` (제어판 '주행 시작'·'맵핑 시작' 은 자동). 노머신 화면 공유도 끊는다. VS Code 안 Claude 도 꺼진다

- [ ] 배터리 완충으로 교체, 전압 기록
- [ ] `race.yaml` 최종 확인: 예선 `obstacles: off` / 결승 `obstacles: lidar`, v_max, 맵·트랙 이름
- [ ] 출발 자리: 맵핑을 시작한 자리·방향 근처
- [ ] 비상 정지 (LB) 한 번 더 확인

## 문제가 생겼을 때 먼저 볼 곳

| 증상 | 먼저 볼 것 |
|---|---|
| `/drive` 가 안 나옴, 차가 안 움직임 | `~/mlcs_data/logs/*_hmpc.log` 에서 노드가 죽었는지 (Traceback) |
| 시작하자마자 "솔버 고장" | B 로 다시 출발. 반복되면 로그와 함께 보고 |
| 위치가 튀거나 벽이 장애물로 보임 | 맵 고정 맞춤 비율, Cartographer 로그. 다시 위치 잡기 (LT 또는 RViz 2D Pose) |
| 한쪽으로 계속 휨 | 4번 조향 중립, 5번 라이다 장착 yaw |
| 급커브에서만 교착·후진 | 그 코너 폭이 차 회전 반경보다 좁은지 (5번) |
| 직선에서 좌우 요동 | 요레이트가 자이로로 나오는지 ("요레이트: 자이로 (wheel_odom) 사용 중") |
