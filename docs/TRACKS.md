## track_5 — 해석적으로 만든 스타디움 (`_generate.py` 있음)

유일하게 생성 스크립트가 남아 있다. 학교 운동장 모양이다:

```
직선 ─ 반원 ─ 직선 ─ 반원   (닫힌 고리, CCW)

  CENTER = (-0.20, -0.20)
  RADIUS = 1.30 m        → κ = 1/R = 0.769
  STRAIGHT = 1.40 m
  WIDTH = 0.60 m
  ROTATE = +20° (CCW)    실험실 경계에 맞추려고 통째로 기울임
  N_POINTS = 600
```

**곡률이 설계로 보장된다** — 반원 구간은 정확히 `1/R`, 직선은 0. 수치
최적화가 아니라 수식으로 찍으므로 "요청한 한계를 못 지키는" 일이 없다.

경계 검사도 한다 — 중심선·좌·우 경계의 **모든 점**이 실험실 경계
(`map_boundary_data.json`) 안에 있는지 확인하고, 벗어나면 에러를 내며
"RADIUS 나 STRAIGHT 를 줄이고 다시 실행하라" 고 알린다.

> 주석에 "single radius R = 1.5 m" 라고 써 있지만 실제 상수는 **1.30** 이다.
> 문서만 안 고친 흔적이다. 값은 `track.json` 과 CSV 가 맞다.

## track_1 — 손으로 클릭한 중심선 (생성 스크립트 없음)

`track.json` 의 `label` 이 "Original lab centerline" 이고, `map_data` 를
추적하면 이 파이프라인이 나온다:

```
record_manual_lab_boundary.py      실험실 경계를 손으로 기록
        ↓
reclick_centerline_with_reference.py   경계 위에 중심선을 손으로 클릭
        ↓  track_reclick_data/latest_reclicked_centerline.json
make_curvature_limited_track.py    곡률을 제한하며 매끄럽게 다듬기
        ↓  track_curvature_data/latest_curvature_limited_track.json
```

마지막 JSON 의 `max_abs_kappa = 3.405804820228344` 가 track_1 의 값과
**완전히 일치**한다 — track_1 이 이 산출물이 맞다.

### ★ 그런데 이 곡률 제한이 **수렴에 실패했다**

`latest_curvature_limited_track.json` 이 그대로 기록하고 있다:

```json
"parameters": { "kappa_max": 1.2,  "dkappa_max": 8.0,  "max_iter": 250 },
"metrics":    { "max_abs_kappa": 3.406,  "max_abs_dkappa_ds": 12.01 },
"converged":  false,
"iterations": 250
```

| | 요청 | 실제 |
|---|---|---|
| `kappa_max` | 1.2 (R = 0.833 m) | **3.406** (R = 0.294 m) |
| `dkappa_max` | 8.0 | **12.01** |

**250회 반복에서 수렴하지 못한 채 멈췄고, 그 결과가 그대로 트랙이 됐다.**

요청대로 `kappa_max = 1.2` 가 지켜졌다면 최소반경이 **0.833 m** 였을 것이다.
우리 차 한계 0.877 m 에는 **아직 살짝 못 미치지만**(필요 조향 21.6° vs
한계 20.6°), 35% 가 불가한 지금과는 차원이 다르다.

정확히 말하면 우리 차의 곡률 한계는 `κ = 1/0.877 =` **1.141** 이다:

| 요청했을 값 | 최소반경 | 필요 조향 | 우리 차 |
|---|---|---|---|
| κ=1.2 (실제 요청) | 0.833 m | 21.6° | ✗ 살짝 초과 |
| κ=1.141 (딱 한계) | 0.877 m | 20.6° | ✗ 여유 0 |
| **κ=1.1** | 0.909 m | 20.0° | ✓ 가능 |
| κ=1.0 | 1.000 m | 18.3° | ✓ 여유 있음 |

즉 **의도 자체가 우리 차에 아슬아슬했고, 그나마도 최적화가 실패해
3배 급한 트랙이 나온 것**이다. 다시 돌린다면 `kappa_max = 1.0` 정도로
여유를 두는 것이 맞다.

> DeepRacer 는 조향각이 커서 0.294 m 도 돌 수 있었으므로 이 실패가
> 드러나지 않았다. 차를 바꾸니 비로소 문제가 된 사례다.

## 그래서 무엇을 할 것인가

### 지금 — track_5 로 시작

```bash
ros2 run mlcs_mpc import_track --ros-args \
    -p src:=<트랙폴더>/track_5 \
    -p out:=~/mlcs_mpc/src/mlcs_mpc/waypoints/track_5.csv
```

`import_track` 이 매번 주행 가능성을 검사하고, 불가하면 이유를 알려준다.

### 나중에 — track_1~4 를 쓰고 싶다면

셋 중 하나다:

**① 곡률 제한을 다시, 제대로 돌린다** (가장 정직한 방법)

`make_curvature_limited_track.py` 를 `kappa_max = 1.0` 정도로 두고
`max_iter` 를 늘려 **수렴할 때까지** 돌린다. 원래 의도했던 결과다.
수렴하면 `converged: true` 가 되고 최소반경이 0.9 m 이상 나온다.

⚠ 곡률을 낮추면 코너가 완만해져 **트랙이 커진다.** 실험실 경계 안에
들어가는지 같이 확인해야 한다 (그 스크립트가 경계 검사를 한다).

**② track_5 처럼 해석적으로 새로 만든다**

`track_5/_generate.py` 가 좋은 본보기다. 반경을 상수로 두므로 곡률이
설계로 보장되고, 경계 검사도 들어 있다. 모양을 바꾸고 싶으면 이걸
복사해서 고치는 편이 수치 최적화보다 안전하다.

**③ 조향각 한계를 실측한다**

`max_steer = 0.36` 은 아직 **추정치**다. 기구 스토퍼까지 실제로 돌려보면
더 클 수 있다. 다만 track_1 이 요구하는 48.3° 는 1/10 스케일 차량에서
비현실적이므로, 이것만으로는 해결되지 않는다.
