# 2026-11-04 학습 데이터 수집과 HyperPM 학습 준비

## 연구 배경 및 목적

HyperPM 학습에 쓸 실주행 데이터를 모으고, 학습 파이프라인이 우리 데이터로 도는지 확인한다.
데이터를 더 쌓기 전에 파이프라인을 먼저 통과시켜, 형식 문제를 일찍 찾는 것이 목적이다.

## 연구 방법

- `./drive.sh joy --log` 로 수동 주행, 조향 분포를 보며 주행 방식을 조정
- `tools/clean_drive_log.py`: mocap 불량 구간 제거 (pose 3프레임 정지, 프레임 간 6 m/s 또는 15 rad/s 초과, 빈 값). 앞 0.2 s, 뒤 1 s 추가 제거
- `tools/prep_hpm_dataset.py`: 저자 형식 변환 (SG 31/2 미분, 뒤축→무게중심, 조향 명령에 ±0.40 제한과 3.2 rad/s 속도 제한, 전진만, run 단위 분할)
- 전자저울로 차를 밀어 마찰 측정

## 연구 진행 상황

분할: train 7.0분 / val 2.0분 / test 1.0분. 분포(v_x, v_y, r, omega, delta, Iq)는 저자 데이터와 비슷하다.

**마찰** (3097 g 기준, 네 바퀴 모두 미끄러짐)

| 방향 | 최대정지 | 운동 |
|---|---|---|
| 옆 | 1400 g → 0.452 | 1340 g → **0.433** (사용) |
| 뒤→앞 | 1490 g → 0.481 | 1400 g → 0.452 |

주행 로그의 1초 평균 횡가속도는 최대 약 0.55 g로, 밀어서 잰 값보다 높다. 뒷바퀴를 고정하면 앞바퀴도 잠겨서 4WD로 확인했다 (`ROADMAP.md` 의 2WD 수정).

**mocap**: 추적 끊김은 y < -3 m 에 몰린다 (주행 시간 대비 30~41%). 대부분 영역 이탈이다. 다만 (1.14, 1.15) 에서도 0.6 s 끊김이 한 번 있었고 원인은 모른다.

**학습 환경**: 저자 코드는 그대로 두고 `hypermpc/hpm/` 에 설정을 얹었다. 젯슨 CPU에서 순전파·역전파 4스텝(배치 32, compile 끔)까지 확인, NaN 없음, 한 스텝 약 4 s. `main.py` 전체 1 에폭은 끝까지 돌리지 못했다 (젯슨 예상 30분 이상).

**저자 코드 주의점**
- `main.py` 에 저자 wandb API 키가 들어 있다 → `WANDB_MODE=disabled` 로 실행
- `main.py` 는 없는 `robot_model.acrobot` 을 import 하고, 저자 차 설정의 신경망이 받지 않는 `free_params` 를 넘긴다 → 우회
- 뒷바퀴 슬립각에 lr 대신 lf 를 쓴다 (저자 FIXME). 비교를 위해 그대로 둔다
- 차 모델의 질량이 코드에 고정되어 있다 → 상속해서 변경
